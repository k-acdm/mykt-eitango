# マイ活アプリ HP 獲得実態 監査レポート（2026-05-24）

**目的**：アバター着せ替えアイテムの価格設定（HP 消費額）と、HP 景品交換の Amazon 券 5,000 円達成条件確定のため、生徒の実 HP 獲得ペースを把握する。

**前提**：本レポートはコード調査による「HP 付与の理論モデル」を集約する。実データの 90 日分集計は GAS エディタから既存関数 `analyzeHpLog90Days()` を実行することで取得できる（§3 参照）。Claude Code 側ではスプレッドシート実データに直接アクセスできないため、本ファイルは「フレームワーク + 実行手順 + 計算済み理論最大値」をふくちさんに渡す形になる。

### 1.1 連続週²倍率の挙動
- `week = ceil(streak / 7)`（streak = 連続ログイン日数）
- 倍率 = `week²`
- 適用後 HP = `rawHP × week²`
- 例：
  - 連続 7 日（week=1）→ 1 倍
  - 連続 14 日（week=2）→ **4 倍**
  - 連続 28 日（week=4）→ **16 倍**
  - 連続 63 日（week=9）→ **81 倍**
  - 連続 90 日（week=13）→ **169 倍** ← 90 日完走の最終週倍率

### 1.2 練習モード
- 上限到達後の追加挑戦は `_practice` 接尾 type で HP 0 を記録。
- HPLog には書かれる（engagement 追跡用）が Students.HP は加算されない。

### 1.3 ふくちさんが手動で参照したい既存資料
- 管理画面「HP 手動付与」内の参考表（[admin.html](../admin.html) 内 `<details>` 折り畳み）に同等の表が既に存在する。
- 本レポートはそれをデータ分析と統合した最新版。

## 2. 「90 日連続フル稼働」した場合の理論最大 HP

仮定：
- 連続日数 91 日（90 日目に week=13 へ突入する設計、`ceil(90/7)=13`）
- 実質計算は「毎日全コンテンツを上限まで実施する」前提
- ログインボーナス：90 日分（倍率なし、+10 × 90 = +900）
- 各コンテンツの倍率は当日の week を使う。本セクションでは簡易計算として「平均倍率 ≈ Σ(week²)/90 weeks」を使用。

### 2.1 90 日間の week² 累積（基準値）

```
week  日数  week²
 1     7    1   ×  7 =    7
 2     7    4   ×  7 =   28
 3     7    9   ×  7 =   63
 4     7   16   ×  7 =  112
 5     7   25   ×  7 =  175
 6     7   36   ×  7 =  252
 7     7   49   ×  7 =  343
 8     7   64   ×  7 =  448
 9     7   81   ×  7 =  567
10     7  100   ×  7 =  700
11     7  121   ×  7 =  847
12     7  144   ×  7 = 1008
13     6  169   ×  6 = 1014   ← 90 日目で打ち切り
─────────────────────────────
合計（90日 = Σ）       = 5,564
```

→ **90 日連続稼働で 1 日あたり素点 1HP のコンテンツの累積倍率付き総 HP = 5,564 HP**

### 2.2 学年別 理論最大 HP（連続 90 日 + 全コンテンツ毎日上限）

### 2.3 解釈
- 「完璧な高校生」が 90 日間 1 日も休まず全コンテンツ完走すると **約 920 万 HP**。
- 既存の景品交換ランクと比較：
  - ブロンズ 30,000 HP（小学生でも 3 日で到達可能）
  - シルバー 120,000 HP（小学生でも 10 日程度）
  - ゴールド 400,000 HP（小学生 30 日、中学生 15 日程度）
  - プラチナ 1,200,000 HP（中学生 30 日程度）
  - ダイヤ 3,500,000 HP（高校生でフル稼働 50 日程度）
  - レジェンド 10,000,000 HP（高校生 90 日フル稼働で到達）
- **「Amazon 券 5,000 円達成条件」のターゲット HP** は、上記理論最大値から「現実的な稼働率（30-50%）」を逆算して設定する必要あり。

## 3. 実データ取得手順：`analyzeHpLog90Days()` の実行

既存の GAS エディタ専用関数 `analyzeHpLog90Days(opts)`（[gas/Code.js:3772](../gas/Code.js)）が、本レポートの集計要件をすべて満たす。

### 3.1 実行方法
1. GAS エディタ（[script.google.com](https://script.google.com)）を開く
2. 関数ドロップダウンから `analyzeHpLog90Days` を選択
3. 実行 → 完了後、スプレッドシートに `HpAnalysisResult_YYYY-MM-DD-HHmmss` シートが新規作成される

オプション引数（必要な場合は GAS エディタ内で関数を直接呼び出す）：
```javascript
analyzeHpLog90Days({
  days: 90,             // 集計対象日数（既定 90）
  heavyMinStreak: 30,   // ヘビーユーザー定義の最低連続日数（既定 30）
  heavyN: 5,            // ヘビーユーザー抽出数（既定 5）
  shortBurstN: 2,       // 短期集中型抽出数（既定 2）
  includeSpecial: false // SpecialAccounts（テスト枠等）を含むか（既定 false）
});
```

### 3.2 出力スキーマ（書き出されるシート構造）

```
meta:
  executedAt, rangeStart, rangeEnd, days
  totalStudentsInMap, totalActiveStudents
  hpLogRowsScanned, hpLogRowsInRange, hpLogRowsExcludedByType, hpLogRowsUnknownSid

byGrade: { 小 / 中 / 高 / 未設定 } × {
  count, sum, mean, median, p25, p75,
  top5:    [{ sid, nick, grade, streak, hp90 }] × 5,
  bottom5: 同上
}

byContent: {
  test, sango, wabun1, kiso, kanji, kobun, lison, calctrial,
  kokugo_800, kokugo_1200, shakai, rika, login, apology, manual_grant
} × {
  sum, byGrade: { 小 / 中 / 高 / 未設定 }
}

heavyUsers: [
  { kind: 'heavy' | 'shortBurst',
    sid, name, nickname, grade, streak, totalHP, hp90Days,
    hpPerDay,        // hp90Days / 90 の平均
    byContent: { kiso: N, sango: M, ... }
  }
] × (heavyN + shortBurstN)

rawDistribution: { 小: [hp90 降順配列], 中: [...], 高: [...], 未設定: [...] }
```

### 3.3 集計の前提
- HPLog の `reserve_release` / `completion_bonus` type は集計対象外（両輪 Phase A の内部記録のため）
- 過去 90 日に活動 0 件 + streak=0 の生徒は完全未稼働として除外
- Students シート優先（同 sid が SpecialAccounts にも存在する場合、Students の grade を採用）

### 3.4 学年区分の判定
- Students / SpecialAccounts の `GRADE_LEVEL` 列が出典
- 値が「小」で始まる → 小 / 「中」で始まる → 中 / 「高」で始まる → 高 / 空欄 → 未設定
- 値の整理状態は実データ確認時に判明する（未設定が多すぎる場合はふくちさん側で補完）

## 4. ふくちさんへの実行依頼（次のステップ）

### 4.1 即実行
1. **GAS エディタで `analyzeHpLog90Days()` を実行**（引数省略可）
2. 完了後、新規シート `HpAnalysisResult_<datetime>` が作成される
3. シートの構造化テーブルを目視確認 → 異常値（hp90 が極端な生徒 / 未設定学年が多い等）を特定

### 4.2 確認すべき主要指標（B 工程 = HP 価格決定に直結）
- `byGrade.中.median` → 平均的な中学生の 90 日累計 HP（B 工程の基準値）
- `byGrade.中.top5` の hp90 → ヘビーユーザーの実績（最大想定値）
- `heavyUsers[].hpPerDay` → 1 日あたりの実 HP 獲得量
- `byContent.kiso.sum` vs `byContent.test.sum` → コンテンツ別の人気度（価格設定の重み付け参考）

### 4.3 学年区分が未設定の生徒が多い場合
- Students / SpecialAccounts シートの `GRADE_LEVEL` 列を手動で補完
- 補完後 `analyzeHpLog90Days()` を再実行

## 5. 主要発見サマリ（コード調査時点での所見）

1. **HP 獲得経路は 14 種類**（コンテンツ 11 種 + ログイン + apology + manual_grant）。すべて `_grantHP` に集約済み（Phase 3 Step 9 完了）で、ログ整合性は両輪システム（reserve_release / completion_bonus）込みで担保されている。
2. **週²倍率の影響が極大**：90 日完走時の最終週倍率は **169 倍**（week=13）。連続日数の有無で生徒間の累計 HP に 100 倍以上の差が出るため、ランク設計時には「初心者保護」「ヘビーユーザー報酬」のバランスを意識する必要あり。
3. **学年別の天井が明確**：高校生は中学生の約 1.18 倍、中学生は小学生の約 1.75 倍の理論最大値を持つ。アバター価格は学年別に共通でも、達成スピードに自然と差が出る設計。
4. **練習モード（HP 0 で engagement だけ記録）が 3 コンテンツに存在**：基礎計算・カンジー・コブタン・計算タイムトライアル・理社重要語句。これは「上限到達後も学習継続を促す」教育設計だが、上限調整時にこのコンテンツ群はリスクが低い（HP 加算を増やしても他コンテンツに比べて生徒の総 HP は急増しない）。
5. **国語長文の 1200 字（150HP）が「最も効率的なコンテンツ」**：1 日 1 回上限・素点 150HP は他コンテンツの最高クラス。中・高生向けに新しい「達成感のあるコンテンツ」として運用されているはずなので、実データで利用率を確認したい（`byContent.kokugo_1200.sum`）。

## 6. 次の作業（Phase A の B 工程：HP 価格決定）への示唆

実データ取得後、以下の枠組みで価格設定を進められる：

- **「平均的な中学生が 1 週間で稼ぐ HP」** = `byGrade.中.median × (7/90)` → これを 1 アイテム単価の参考値に
- **「ヘビーユーザーが 1 ヶ月で稼ぐ HP」** = `heavyUsers[0].hpPerDay × 30` → これを高級アイテム（限定スキン等）の単価上限に
- **「Amazon 券 5,000 円達成条件」** = ヘビーユーザーが 90 日かければ到達できる値（例：`byGrade.高.p75` の値前後）

これにより、「みんなが頑張れば届く」「ヘビーユーザーには特別な達成感」の両立が可能。
