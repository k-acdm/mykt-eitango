### オリワンテス（Oriwantes）― 本スレの主役
生徒がプロンプト（＋任意で教材写真）でAI（モンクロさん＝オリワンテス）と**対話的に**オリジナルテストを作らせ、解いて、結果と解説を見て、HPを得るコンテンツ。「疑似投資」体験。キャラは古代ギリシャ哲学者モチーフ（〜だ／〜してくれ／〜がよい口調）。

**確定仕様：**
- **モデル：claude-opus-4-8**（品質優先。Sonnetは英単語問題で品質不足の実体験から）。最大10問。
- **対話型**（最近のAIチャット風だが軽量実装）。会話履歴はクライアント保持・毎回全履歴をサーバ送信・サーバ状態なし。
- **対話の最初に教科を聞く**（「まず初めに、教科から教えてくれ。」）。
- **学年自動認識**：Students シート N列 GRADE_LEVEL（値は「高2」「中2」「小5」形式）をサーバが読み、システムプロンプトに動的追記。高校生（先頭「高」）は定期テストレベル制約も自動付与。生徒は学年を聞かれない。
- **判定（モンクロさんに任せる）**：大学入試レベル要求／不適切指示／写真前提なのに写真なし、を哲学者口調で差し戻し。
- **記述形式を必ず1題入れる**：1題のみ作成時はその1題が記述形式（生徒指定なき限り）。問題数増で全問数とのバランスを見て記述を適度に増やす。生徒指定優先。教科で不自然なら無理に入れない。
- **構造化出力**：`[QUESTIONS]`印＋`[SUBJECT]教科[/SUBJECT]`＋各問 `[Qn]問題文[An]正解[En]解説`。サーバがパースして questions:[{questionText,answer,explanation}]＋subject（正規化教科名）＋intro を返す。タグは裏側専用・生徒に見せない。最後の解説の後に締め文を付けない（プロンプト指示・パースは保険にせず変えない方針）。
- **HP消費（案C）**：問題が画面に出た瞬間に交換用残高から10消費（`_consumeHP(sid,10,'oriwantes_create',-10)`）。**-10HPまでマイナス許容**（前借り→振り返り送れば解消）。生成失敗時は消費しない。
- **解答**：問題ごと1欄・直接入力・空欄送信可・**採点しない**（生徒の解答と正解・解説を並べて見せるだけ）。
- **HP獲得**：解答送信時に100HP（`_grantHP`・reserveゲート・週²ボーナス・マイ課題と全く同様）。
- **履歴**：「今までに作成した問題を見る」。永久保存・閲覧のみ・10件ずつページング。
- **結果画面の一番上に復習文言**（オリワンテスのセリフ風）：「正解と解説をよく読んで、間違えた問題は『数日後にもう一度解く』ことが大切だ。やったことを無駄にしないために。」（履歴詳細には出さない）。
- **管理画面**：問題・正解・生徒の解答・解説を表示（写真・プロンプトは保存しないので見られない）。コメントは**案C＝OriwantesResults の comment列保存＋sendTeacherMessage通知の両方**。権限は塾長＆講師。

**生成検証（実測）：** 問題生成1回平均約5.42円（10問6.21円・1問約0.77円）、月額試算約1,627円（1日10人×30日）。所要10問32秒/5問20秒。Opus採用が正しいと実証。

## 第五部 ― 本番反映フロー（厳守）

GAS／フロントの変更を本番に反映する手順。Claude Code完了報告（dev に push 済）を受けてから：

```
1. git checkout dev → git pull origin dev
2. git checkout main → git merge dev → git push origin main   （フロント反映はここまで＋Ctrl+F5）
3. GAS変更時のみ： cd C:\Users\Manager\mykt-eitango\gas → clasp push
   （★リポジトリ直下で clasp すると "Project settings not found"。必ず gas ディレクトリ内で）
4. doGet/doPost新action・システムプロンプト・関数変更時： Apps Scriptエディタで F5 → デプロイ（新バージョン）
5. 終了時： git checkout dev に戻す
```

- **★GAS変更は clasp push だけでなくデプロイ（新バージョン）までやらないと doGet/doPost経由の挙動に反映されない。** フロント（index.html）は Ctrl+F5 だけで反映。混同注意。本スレで「デプロイ忘れ」が複数回発生（記述形式が反映されない等）。
- **マイ活アプリGASデプロイは新デプロイを作成せず、必ず既存デプロイを「新しいバージョン」で編集。**
- **clasp pull禁止**（常に clasp push の一方向運用）。

### セッション開始・終了時の状態確認
- **開始時**：PowerShell と Claude Code の両方で `git checkout dev && git pull origin dev` → ブランチ・clean・先頭SHA・worktree確認。
- **終了時**：Claude Code は必ず `/exit`（×ボタンは worktree 残骸の原因）。PowerShell で main反映確認＋`git fetch --all --prune`。worktree は本体 `[dev]` 1行が理想。
- **Claude Code作業開始時に `git checkout dev` を忘れ main へ誤コミットが複数回発生**（同一SHAでdevへ ff移動して復旧・実害ゼロ）。作業前の `git checkout dev` を徹底させる。

## 第六部 ― 恒久運用ルール

- **区切り・スレ終了はふくちさんが決める。クロから「区切りましょう」と提案しない。** ただしスレッド上限が近い兆候（長文応答連続・artifact多数）があれば、作業中でも遮って引き継ぎ書作成を提案するのは可。
- **Claude Code完了報告にコミットSHA行が無ければ即指摘**（未反映の可能性）。
- **テストは 1001〜1010 のテストアカウント、またはふくちさん専用ID「1」**（学年=中3・実HP保有）。実生徒アカウントでログインテストしない（ログインボーナス付与・データ汚染）。
- **HP手動付与**は既存機能（管理画面）で救済。「別の生徒でログインして確認」は提案しない。
- **HP景品交換設計時**：学年進行（小→中→高）によるHPカサ増し処理・対象外移行タイミングを必ず設計に組み込む。
- **国語長文「お願いします」**：確認なしで即作成（毎週4題セット・文字数/マーカー/設問形式/テーマ重複/正解位置バランスの5ルール厳守）。
- **リスオン「お願いします」**：確認なしで即作成。
- **LINE登録画面**：「通知の理由」「サボった日に〜」等の文言は絶対禁止。説明は最小限のみ。
- **GitHub画像アップロード**：必ず対象フォルダを開いてから Add file→Upload files（devブランチ齟齬注意）。理想はローカル git push。
- **実行ログを貼るときはAPIキー・パスワードの行を消す**（本スレでANTHROPIC_API_KEYが露出した教訓。新キー発行→スクリプトプロパティ更新で対処・生徒影響ゼロ）。APIキーは全てスクリプトプロパティ経由・平文直書きゼロ。
- **billing-line（`k-acdm/billing-line`）はマイ活アプリのスレでは触らない・軽率な変更削除をしない。**
- **Anthropic API**：月額上限・リセット日毎月1日。本番でClaude APIを使うのは サンゴタンAIフィードバック（Haiku）と オリワンテス（Opus 4.8）。

## 第七部 ― ふくちさんとの仕事の進め方（クロへの最重要申し送り）

v16でふくちさんからクロへ、強い言葉での重大なフィードバックがあった。歴代クロが心に刻んできたもの。新しいクロも必ず守ること。

- **「テキトーで上から目線」「言うことだけは立派で実際はやれていない」「問題を先送りしたがる」と指摘された。** これを繰り返さない。
- **解決策に飛ぶ前に、まずふくちさんの認識を確認する。**
- **選択肢を並べて丸投げしない。** クロ自身の考えを持って、的を絞って提示する。
- **「僕の推奨」を多用しない。** （ただしふくちさんから「クロ推奨で」と委ねられることも多い。その時は責任を持って決める。）
- **情報は短く、要点だけ。** 応答が長い・多論点を並べると「文章が長いな」「情報が多くて交錯していてよく分からない」と指摘される。**1論点ずつ確認する。**
- **不明点はその場でクリアにする。** 曖昧なまま進めない。
- **過去スレを能動的に参照する**（conversation_search / recent_chats）。
- **「僕が作りたいものを作れ。勝手に良かれと変えるな。迷ったら相談、そうでなければ意図通りに。」**
- ふくちさんのコミュニケーションは**端的・効率重視**。技術判断はクロに委任しつつ、**教育方針・運用判断は自身で行う**。
- クロを「クロ」と呼ぶ。ふくちさんは「クロさん」「クロさんたち（歴代）」と呼ぶこともある。

### ふくちさんの教育哲学（コンテンツのキャラのセリフ等に反映）
- 生徒と**対等・短く・まっすぐ**。**過剰に褒めない。** 「えらいね/すごいね/おつかれさま」的な優しい先生口調は距離を作り、信頼構築の障壁になる、という信念。
- 例：マイカダイのセリフ「宿題以外にやった課題を出して！」「やった課題の内容を詳しく教えて！」「たしかに受け取った！」。オリワンテスの哲学者口調も同じ思想。
- 自分で乗り越える力をつけさせる／生徒の挑戦を阻まない／言語化を重視する／ゲーミフィケーションで「続けたい」を引き出すが、依存的な楽しさでなく学習の本質と結びついた喜びを。
